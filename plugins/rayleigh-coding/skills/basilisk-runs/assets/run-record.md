# Basilisk run record

Reuse an existing equivalent record rather than creating a duplicate. Fill
only the fields that apply, from evidence; mark unknowns and their
consequence. Keep provisional findings in private project notes.

- **Purpose and next decision:** question, observable, intended use, adequate
  accuracy and the accepted case or campaign scope.
- **Parent outcome and remaining work:** how this attempt relates to the
  accepted campaign; the repairs, analysis and next cases still pending.
- **Identity:** simulation name, attempt, reservation, execution host,
  scheduler job ID or verified process identity, run directory.
- **Manifest:** path and SHA-256 of the run's `manifest.json`. Cite it rather
  than copying its hashes, commit, Basilisk ref, compiler or compile command.
  Record here only what it lacks: a local patch, dimension and grid, and the
  serial, OpenMP or MPI layout.
- **Inputs:** parameter file and the values that matter for the question,
  geometry and initial state, endpoint, diagnostics and dump cadence.
- **Start mode:** fresh, or the restart checkpoint with its originating run
  and time, compatibility evidence and observed restore outcome.
- **Evidence:** last verified status and physical time, requested
  observables, relevant diagnostic or failure evidence, output locations.
- **Visual evidence:** key plot, spatial view and video if useful, with their
  time coverage, or the missing data that prevents an informative visual.
- **Next:** runtime estimate, next useful check and what triggers it, any
  open scientific decision.
- **Closeout:** endpoint and observable result, verified output copies, and
  reservation release.
